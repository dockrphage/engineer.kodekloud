# **README.md (Umbrella Repository)**  
## **Engineer.KodeKloud — Task Sets Umbrella Repository**

This repository serves as the **umbrella workspace** for all hands‑on task sets from the  
**Engineer.KodeKloud Practice Platform**.  
Each task set lives in its own directory and will receive an individual README once its tasks are completed.

This root README provides the **high‑level structure**, purpose, and navigation for the entire collection.

---

## **📁 Repository Structure**

The repository contains folders representing different learning tracks and challenge sets, such as:

- **100 Days of Cloud**  
- **100 Days of DevOps**  
- **Terraform L1/L2 Task Sets**  
- **Jenkins Task Sets**  
- **Kubernetes / Docker / CI-CD Tracks**  
- **Additional KodeKloud Engineer Tracks**  

Each folder contains:

- A structured set of tasks  
- Hands‑on implementations  
- Supporting scripts, IaC, or automation  
- A dedicated README (added once the task set is completed)

---

## **🎯 Purpose of This Repository**

This repo acts as a **centralized workspace** for:

- Tracking progress across multiple KodeKloud Engineer task sets  
- Maintaining clean, reproducible implementations  
- Organizing long‑term learning across DevOps, Cloud, IaC, CI/CD, and automation domains  
- Providing a single entry point for all sub‑projects  
- Enforcing consistent structure, naming, and documentation standards

It is intentionally minimal at the top level — detailed documentation will live inside each task‑set folder.

---

## **🧭 Navigation**

Each task set is self‑contained.  
To explore a specific track, navigate into its folder:

```
cd 100-days-of-cloud/
cd terraform-l1/
cd jenkins-tasks/
```

Inside each folder, you will find:

- Task‑specific code  
- Notes and explanations  
- Scripts and IaC  
- A dedicated README (added after completing the tasks)

---

## **🛠️ Conventions Followed**

This repository follows consistent conventions across all task sets:

- **Directory names** use hyphens or underscores for clarity  
- **Each task** gets its own folder when applicable  
- **Each task set** gets its own README  
- **Infrastructure code** follows reproducible, minimal‑state patterns  
- **Git hygiene** is maintained (no local state, no secrets, no clutter)
